# 드레스 투어 기록을 AI와 비교 사이트로 정리한 과정

드레스 투어를 하고 나면 사진만으로는 남지 않는 정보가 있어요. 어떤 순서로 입었는지, 상체 주름이 어땠는지, 두 사람이 각각 무엇을 좋게 봤는지 같은 내용이죠.

이번에는 마리에드오늘·클라인브라이덜·렌느브라이덜 세 업체의 자료를 모으고, 스케치와 피팅 사진, 인스타그램·블로그 후보를 비교하는 사이트를 만들었어요. 처음에는 실루엣별 사진 모음이었는데, 작업하면서 실제 피팅 기록을 중심으로 구조를 바꿨습니다.

이 글은 특정 드레스를 추천하는 글이 아니라, 흩어진 자료를 어떻게 정리하고 어디까지 확인했는지 남긴 작업 기록이에요.

## 사진을 모으기 전에 업체와 피팅 순서부터 맞췄어요

처음 요청은 A라인·벨라인·머메이드·슬림 같은 분류로 드레스 사진을 모으는 것이었어요. 여기에 업체별 목록과 소재 태그를 붙이고, 통합 페이지에서도 전체 사진을 볼 수 있게 했습니다.

그다음 실제 투어 기록이 들어왔어요. 같은 네 벌을 두 사람이 각각 그린 스케치와 의견 메모였고, 촬영이 가능했던 곳의 피팅 사진도 있었어요.

여기서 먼저 해야 했던 일은 사진 속 디자인을 분석하는 것보다 **기록이 어느 업체의 몇 번째 드레스인지 확정하는 것**이었어요. 용지에 인쇄된 업체명과 실제 기록한 업체가 다른 경우가 있었고, 사진의 순서도 대화 중에 정정됐거든요.

최종적으로 사용자가 확인한 업체와 순서를 기준으로 연결했어요. 한 드레스를 여러 각도에서 찍은 사진은 같은 피팅 번호로 묶고, 두 사람이 그린 같은 드레스를 별도 제품으로 세지 않았습니다.

## 두 사람의 기록을 합쳐 쓰지 않았어요

스케치는 형태를 기억하는 자료이면서 현장에서 느낀 점을 남긴 자료이기도 했어요. 그래서 두 원본을 모두 남기고, 각 드레스 아래에 기록자 1과 기록자 2의 의견을 구분했습니다.

정리할 때는 디자인 메모와 개인 감상도 나눴어요. ‘일자탑’, ‘허리 주름’은 관찰한 형태이고, ‘단아하다’, ‘가장 마음에 든다’는 개인 의견이니까요. 읽히지 않는 손글씨는 문맥으로 채우지 않고 판독 불가로 표시했습니다.

번호별로 잘라 둔 스케치만으로는 옆 칸에 걸친 메모를 놓칠 수 있어요. 그래서 세 업체 모두 **기록 1 전체 보기·기록 2 전체 보기**를 제공했습니다. 렌느도 마지막에 같은 방식으로 보완했고, 두 원본이 실제로 확대해서 열리는지 확인했어요.

## 피팅 자료가 먼저 보이도록 화면을 바꿨어요

렌느는 스케치를 중심에 두고 실제 피팅 사진을 옆에서 비교하도록 구성했어요. 인터넷에서 찾은 사진은 아래쪽으로 옮기고 기본적으로 접어뒀습니다.

실제 입었던 드레스와 인터넷에서 찾은 후보는 정보의 확실성이 달라요. 한 화면에 같은 비중으로 놓으면 후보가 실제 제품처럼 읽힐 수 있습니다. 그래서 ‘실제 피팅’, ‘스케치 기록’, ‘비교 후보’를 구분하고, 후보에는 출처와 미확정 표시를 붙였어요.

화면을 설계할 때도 이런 구분이 필요했습니다. 사진이 많다고 모두 처음부터 펼쳐둘 필요는 없었어요. 기본 화면에는 직접 기록한 자료와 의견을 놓고, 외부 후보는 필요할 때 펼쳐 비교하는 편이 요청한 사용 방식에 맞았습니다.

## 태그는 사진에서 보이는 것과 확인된 사양을 나눴어요

실루엣과 소재만으로는 비슷한 드레스를 구분하기 어려워서 목선, 소매, 장식, 표면, 촬영 구도 같은 항목도 사용했어요.

| 분류 | 기록할 수 있는 내용 | 주의한 점 |
|---|---|---|
| 실루엣 | A라인·벨라인·머메이드·슬림 | 정면만 보고 경계를 확정하기 어려운 경우가 있음 |
| 표면 | 매끈한 광택·비치는 망사·레이스 무늬 | 조명과 베일이 원단처럼 보일 수 있음 |
| 소재 | 업체 설명에 적힌 실크·새틴·미카도 등 | 사진만으로 실제 섬유나 원단을 확정하지 않음 |
| 구조 | 목선·몸판 절개·주름 방향·허리 위치 | 꽃다발이나 팔에 가린 부분은 미확인 |
| 장식 | 비즈·꽃 모티프·리본·레이스 | 드레스 장식인지 베일 장식인지 구분 |

특히 실크·새틴·미카도는 같은 기준의 이름이 아니에요. 실크는 섬유, 새틴은 직조 방식에 관한 말이고, 미카도는 드레스 원단을 설명할 때 쓰이는 명칭입니다. 공유 스킬에서도 이들을 서로 배타적인 정답처럼 고르게 하지 않고, 출처의 소재 설명과 사진에서 본 외관을 별도로 기록하도록 했어요.

나중에 추가로 가져온 사진에는 기존 대표 사진의 태그를 그대로 복사하지 않았습니다. 같은 게시물 안에서도 드레스나 구도가 달라질 수 있어서, 개별 분류가 끝나지 않은 사진은 그 상태를 표시했어요.

## 같은 드레스를 찾는 기준을 구체적으로 바꿨어요

처음에는 비슷한 실루엣과 원단 느낌을 기준으로 후보를 찾았어요. 하지만 사용자 피드백이 들어오면서 비교할 부분이 더 구체적으로 바뀌었습니다. 상체에서 배까지 이어지는 선, 벨라인에 가까운 풍성한 A라인, 주름과 허리 경계 같은 특징이 중요했어요.

클라인 4번은 실제 뒷모습 사진이 추가되면서 베일을 단서로 다시 찾았습니다. 넓은 망사 위에 꽃과 잎 자수가 있고, 긴 밑단 쪽에 무늬가 모여 있는지를 봤어요. 짧은 입체 꽃 베일이나 큰 꽃의 윤곽선만 있는 베일은 실제 사진과 달랐습니다.

여기서도 같은 베일을 찾는 것과 같은 드레스를 찾는 것은 별개의 확인이에요. 베일은 다른 드레스에 조합할 수 있으니까요. 베일이 같아 보이면 같은 게시물의 드레스 목선·몸판·허리·치마를 다시 비교해야 합니다.

## 여러 장 게시물과 릴스는 따로 다뤘어요

인스타그램 게시물의 첫 사진을 가져왔다고 그 게시물을 전부 확인한 것은 아니었어요. 여러 장 게시물은 마지막 장까지 확인하고, 각 장의 사진을 구분해야 했습니다.

실제로 슬라이드 전환 직후 이전 이미지 주소가 다시 잡히는 문제가 있었어요. 넘긴 횟수만 세면 검토가 끝난 것처럼 보일 수 있어서, 전환 횟수와 고유 사진 주소를 대조하고 문제가 있었던 구간을 다시 수집했습니다.

또 이미지가 없다고 기록했던 일부 게시물은 릴스였어요. 이후에는 영상을 시작부터 끝까지 시간대별로 확인했습니다. 약 1초 간격의 장면 검토였고, 영상의 모든 프레임을 검사한 것은 아닙니다. 얼굴과 상체만 나오는 영상에서는 긴 베일의 밑단을 판정할 수 없었어요.

## 병렬 작업은 구간과 완료 기준을 나눠서 진행했어요

검토 속도를 높이기 위해 에이전트마다 게시물 구간을 나누고, 릴스도 별도로 맡겼어요. 각 담당자는 자기 결과 파일에만 기록하고, 사이트에 합치는 작업은 한 곳에서 진행했습니다.

중간에는 다운로드가 실패하거나 오래 대기한 작업도 있었어요. 그때는 이미 내려받은 원본과 추가 슬라이드를 출처별로 연결해 검토했습니다. ‘주소를 확보했다’, ‘파일을 받았다’, ‘사진을 눈으로 봤다’는 서로 다른 상태였어요.

수집 기록을 합칠 때도 이전 상태가 최신 파일을 덮어쓰는 문제가 있어 누락 구간을 재확인했습니다. 공유 스킬에는 작업자별 파일을 분리하고, 기존 사진 번호를 유지하면서 병합하는 규칙을 넣었어요.

## 최종 결과는 찾지 못한 부분까지 포함해 남겼어요

이번 작업 시점의 통합 갤러리는 추가 사진 52장을 포함해 2,082장이었어요. 이는 세 업체 자료를 합친 **사진 항목 수**이며, 서로 다른 드레스 2,082벌이라는 뜻은 아닙니다.

클라인 공식 프로필에는 게시물 339개가 표시됐고, 수집 목록도 중복 없는 URL 339개였습니다. 수량이 맞는다는 것만으로 계정의 모든 콘텐츠를 빠짐없이 확보했다고 단정하지는 않았어요. 스토리나 태그된 게시물은 별도 범위입니다.

마지막으로 남아 있던 일반 게시물 99개·사진 112장과 릴스 7개를 나눠 검토했지만, 실제 피팅 사진과 같은 베일로 확인된 새 후보는 없었습니다. 그래서 동일 드레스 후보를 새로 추가하지 않았어요.

비교 사이트에 남긴 것은 사진 모음뿐 아니라, 어떤 자료를 근거로 연결했고 무엇은 아직 미확정인지에 대한 기록입니다.

## 이 과정을 재사용할 수 있게 스킬로 묶었어요

함께 공유하는 `dress-evidence-review` 스킬은 스케치·피팅 사진·외부 게시물을 연결할 때 쓰는 작업 지침입니다. 특정 업체 계정이나 개인 사진은 포함하지 않았어요.

주요 내용은 업체와 피팅 번호 확정, 두 사람 의견의 분리 전사, 사진과 제품 수 구분, 캐러셀·릴스 검토 상태 관리, 동일 제품 판단, 기존 사이트에 중복 없이 반영하는 방법입니다. 검토 기록을 검사하는 작은 Python 도구도 넣었습니다.

예시 요청은 아래처럼 쓸 수 있어요.

> $dress-evidence-review 스케치 두 장과 피팅 사진을 업체별·피팅 순서별로 묶어줘. 두 사람 의견을 구분하고 판독이 어려운 글씨는 표시해줘. 외부 후보는 출처와 일치·불일치 근거를 붙이고, 실제 사진 옆에서 비교할 수 있게 정리해줘.

이 스킬은 로그인 권한이나 수집 권한을 만들어 주는 도구가 아닙니다. 사용 환경에서 접근할 수 있는 자료를 대상으로, 확인한 범위와 남은 부분을 명확하게 기록하도록 만든 지침이에요.
